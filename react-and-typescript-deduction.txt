Type vs Interface

z roku na rok stają się do siebie co raz bardziej podobne

największa różnica polega na extending an interface or a type

interface może rozszerzać nie tylko inny interaface ale również type

rozszerzanie interface'ow:
interface Employee {
  name: string;
  title: string;
}
interface NameTagProps extends Employee {
  level: number;
  isOnline: boolean;
}

ale jeśli to type ma rozszerzać type to wtedy składnia jest nieco inna:

type Employee = {
  name: string;
  title: string;
};
type NameTagProps = Employee & {
  level: number;
  isOnline: boolean;
};

Nazywa to się Intersection

Niuansem jest nadpisywanie rzeczy
bo w interface nie można nadpisać pola innym typem
a w intersection nie ma błedu kiedy się nadpisze

type Employee = {
  name: string;
  title: string;
  level: number;
};
type NameTagProps = Employee & {
  level: number;
  isOnline: boolean;
};

Another comparison: Interfaces can only describe object shapes and, if an interface is declared multiple times, then it merges with previous declarations.

How can you make the children prop mandatory instead of optional when using custom prop types in React?

Instead of using PropsWithChildren (which makes children optional with a question mark), you can manually define children in your type with the type React.ReactNode without the optional operator. For example: type BoxProps = { children: React.ReactNode; width: number; height: number; }

When pulling out an event handler function in React with TypeScript, what information does TypeScript require you to provide?

TypeScript requires type hints for the event handler, such as specifying it as a ChangeEventHandler for an HTMLInputElement or a MouseEventHandler for a button element.

What is the purpose of using ComponentPropsWithoutRef in React with TypeScript when creating custom components that wrap HTML elements?

ComponentPropsWithoutRef allows you to automatically include all the attributes and props from a standard HTML element (like form, button, etc.) in your custom component without having to implement them one by one. This ensures your component supports all native HTML attributes, ARIA tags, event handlers, and other properties of the underlying element.

How can you extend a custom component's props to include all the properties of an HTML form element using TypeScript?

How can you extend a custom component's props to include all the properties of an HTML form element using TypeScript?

Click to reveal answer
You can use ComponentPropsWithoutRef with a generic type parameter specifying the HTML element. For example: ComponentPropsWithoutRef<'form'>. This can be used with an intersection type or by having an interface extend it: interface CounterFormProps extends ComponentPropsWithoutRef<'form'> { }

What is the difference between ComponentProps and ComponentPropsWithoutRef in React TypeScript?

ComponentPropsWithoutRef excludes the ref prop from the component's props, while ComponentProps includes it. ComponentPropsWithoutRef is often preferred because you can handle refs separately using forward ref, higher order components, and useImperativeHandle, giving you more control over ref behavior.
